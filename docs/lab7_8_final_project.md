## 期末综合项目：Apollo 节点自动化守护与监控系统 (Final Project)

- **适用课程**：Linux 操作系统
- **推荐学时**：6 学时 (第 7 周、第 8 周)
- **实验平台**：Earendel Web OS [https://earendel.techarts.cn]
- **期末占比**：60%

---

### 项目导言与背景

> **“在真正的生产环境中，能够用一条命令解决的事情，绝不敲第二条；能够用脚本自动化的工作，绝不手动干预。”**

**业务场景 (Roleplay)**：
阿波罗研发中心 (Apollo R&D) 的微服务节点即将大批量上线。作为运维架构师，你无法手动登录到成百上千台服务器上去逐一建用户、配权限、改防火墙、起服务。
中心主管交给你一个终极任务：编写一个**“一键式自动化守护脚本” (`apollo_guardian.sh`)**。

这个脚本将作为本门课程的**最终结业交付物**。你需要将 1-6 周学到的所有知识（文件、权限、文本处理、进程、网络、防火墙、Shell编程）全部融合进这一个脚本中。
*(注：业界深知大家会使用 AI 大模型辅助编程，这是被允许甚至鼓励的。但你必须深刻理解 AI 生成的代码，因为期末验收时，教师不仅测试脚本功能，还会抽查关键代码的逻辑含义。)*

---

### 核心交付物要求

每位学生最终需要提交一个名为 **`apollo_guardian.sh`** 的 Shell 脚本文件（需支持多次重复执行而不报错，即具备幂等性）。
执行该脚本后，系统需自动完成以下**五大核心任务**。

#### 任务一：系统环境与权限初始化 (对应 Week 1-2)
脚本运行时，需自动执行以下环境配置：
1. **用户与组检查**：检测系统是否存在名为 `apollo_team` 的用户组和 `apollo_svc` 的用户。如果不存在，则自动创建该组，并创建该用户加入组中。
2. **工作目录安全基线**：自动创建应用核心目录 `/data/apollo_core/` 和日志目录 `/var/log/apollo/`。
3. **权限精准控制**：将 `/data/apollo_core/` 的所有者设置为 `apollo_svc:apollo_team`，并将其权限严格设定为 `770`（仅属主和属组拥有完全权限，其他人禁止访问）。

#### 任务二：动态生成与启动微服务 (对应 Week 4, 6)
脚本需包含自动化部署逻辑：
1. **源码生成**：通过 Shell 的 `cat << EOF` 技术，在 `/data/apollo_core/` 目录下自动生成一个 `server.js` 文件。该 JS 代码无需复杂逻辑，只需不断循环打印心跳信息即可（例如使用 `setInterval` 每 5 秒输出一次 `[Heartbeat] Apollo Node is Running...`）。
2. **进程守护与启动**：脚本需通过 `ps` 或 `pgrep` 检查 `server.js` 是否已经在运行。
   - 如果未运行，则使用 `ecc` 工具链将其放入**后台**启动（如 `nohup ecc /data/apollo_core/server.js > /var/log/apollo/app.log 2>&1 &`）。
   - 如果已运行，则跳过启动步骤，并在终端打印绿色提示信息：`[OK] Apollo Service is already running.`

#### 任务三：网络防火墙自动策略 (对应 Week 5)
服务器安全不可忽视，脚本需自动配置 `ufw` 防火墙：
1. **基础防线**：确保 `ufw` 防火墙处于开启状态，并放行 SSH 的 `22` 端口以及微服务预留的 `9090` 端口。
2. **黑名单动态阻断**：脚本在同一级目录下会读取一个名为 `blacklist.txt` 的文件（每一行是一个恶意的 IP 地址，如 `192.168.1.100`）。脚本需使用 `while read` 循环读取该文件，并通过 `ufw deny` 批量将这些 IP 封杀在网络层。

#### 任务四：日志审计与恶意 IP 自动提取 (对应 Week 3)
运维不仅要配置，还要具备分析能力。
1. 假设系统产生了一个名为 `web_access.log` 的访问日志文件（学生需在脚本开头自动生成几行带 404 错误和恶意 IP 的模拟日志数据）。
2. 脚本需使用强大的管道和文本处理工具（`grep`, `awk`, `sort`, `uniq`），自动从 `web_access.log` 中找出出现 `404` 错误次数最多的那个 IP 地址。
3. 将这个找出来的恶意 IP 自动追加写入到 `blacklist.txt` 中，使得下一次执行本脚本时，防火墙会自动封堵该 IP！

#### 任务五：生成节点状态快照报告
在脚本执行的最后，自动收集当前系统的各项状态，生成 `/var/log/apollo/node_status.txt` 报告，并在终端打印出内容，以便教师验收：
- 当前服务器的时间戳 (`date`)
- `server.js` 的进程运行状态及 PID (`ps aux | grep ecc`)
- 当前防火墙的封堵列表 (`ufw status`)
- 开发该脚本的学生签名（学号 + 姓名）

### 项目验收标准与提交流程

#### 1. 提交材料（刻盘存档用）
将以下文件打包为一个压缩包（如 `20260001_ZhangSan_Final.zip`）：
1. `apollo_guardian.sh` （核心业务脚本，代码需包含充分的中文注释）
2. `node_status.txt` （执行该脚本后最终生成的服务器状态快照报告）
3. *（可选）`README.md` 项目设计思路简述。*

#### 2. 评分细则（满分 100 分，占总评 60%）

| 考察维度 | 分值 | 验收关注点 |
| :--- | :---: | :--- |
| **基础环境与文件权限** | 20分 | `id apollo_svc` 正确；`/data/apollo_core` 权限确认为 `770` 且属主正确。 |
| **应用部署与进程守护** | 25分 | JS 文件是否自动生成；后台进程是否成功运行；**幂等性**测试（连续运行两次脚本，不能启动两个相同的进程）。 |
| **文本处理与安全联动** | 30分 | `awk`/`grep` 提取最高频 404 IP 的逻辑是否严密；黑名单是否能成功传递给 `ufw` 形成闭环。 |
| **Shell 语法与鲁棒性** | 15分 | 脚本是否有变量定义、`if` 状态判断、`while`/`for` 循环；是否有良好的运行日志 `echo` 提示。 |
| **代码注释与现场答辩** | 10分 | 代码结构清晰；教师抽问脚本中某一行（如 awk 命令或 nohup 含义）能流利作答。 |

### 💡 给同学们的特别提示 (Tips for AI/LLM Users)
如果你打算使用 ChatGPT / Claude / 文心一言 等 AI 助手来协助完成此项目，**强烈建议**：
1. 不要把整个题目一次性贴给 AI，因为 AI 很容易生成一坨极其复杂且脱离 Earendel 平台实际环境的代码。
2. **拆解任务，逐个击破**。先让 AI 帮你写“检查并创建用户的代码”，测试通过后，再问“如何用 nohup 启动后台进程”，最后自己把它们拼装起来。
3. 务必搞懂 `awk` 提取 IP 的那一串命令是什么意思，这是答辩的必考点！
