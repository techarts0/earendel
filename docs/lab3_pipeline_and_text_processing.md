## 实验三：数据流管道与文本处理三剑客 (Grep/Sed/Awk)

- **适用课程**：Linux 操作系统
- **推荐学时**：3 学时 (讲授 1 学时，练习 2 学时)
- **实验平台**：Earendel Web OS [https://earendel.techarts.cn]

---

### 实验目标

1. **掌握 I/O 重定向与文件描述符机制**：深刻理解标准输入（STDIN 0）、标准输出（STDOUT 1）、标准错误输出（STDERR 2）的工作原理，熟练运用 `>`, `>>`, `<`, `2>`, `2>&1` 控制数据流向。
2. **领悟 Linux 管道（Pipe）哲学**：理解“小工具组合解决大问题”的 Unix 哲学，熟练运用 `|` 将多个单功能命令串联成高效的数据流处理生产线。
3. **熟练掌握长文本交互查看工具**：深入理解 `cat`、`more`、`less` 的适用场景与机制差异，熟练掌握 `less` 在大文件中的平滑滚动、关键词前向/后向检索与首尾快速跳转。
4. **精通辅助文本清洗与统计工具**：熟练运用 `head`, `tail`, `wc`, `cut`, `sort`, `uniq`, `tr`, `tee` 进行多维数据清洗、切片、排序与频次去重统计。
5. **熟练掌握文本处理三剑客**：
   - **Grep**：行过滤神器，掌握常见正则匹配、忽略大小写（`-i`）、行号显示（`-n`）、反向匹配（`-v`）及计数（`-c`）。
   - **Sed**：流式编辑器，熟练运用打印（`p`）、删除（`d`）、精准替换（`s/old/new/g`）等行编辑指令。
   - **Awk**：文本列处理与报表分析利器，掌握列切分（`-F`）、内置变量（`$0`, `$1~$N`, `NF`, `NR`）、条件过滤与格式化输出。
6. **具备真实生产日志分析能力**：能够综合运用管道流与三剑客，对真实 Web 服务器访问日志完成恶意 IP 溯源、状态码分布统计及异常流量排查。

### Part A：核心知识点解析与自由练习

---

#### 1. 理论精讲：输入输出重定向与文件描述符

操作系统进程在启动时，默认会自动打开三个核心数据流通道：
```text
               ┌───────────────────────┐
键盘输入 ─────►│ 0: 标准输入 (STDIN)   │
               │                       │
               │      当前运行进程     │──────► 1: 标准输出 (STDOUT) ─────► 屏幕控制台
               │                       │
               │                       │──────► 2: 标准错误 (STDERR) ─────► 屏幕控制台
               └───────────────────────┘
```

| 符号 | 描述 | 功能与应用场景 | 典型示例 |
| :--- | :--- | :--- | :--- |
| `>` | 输出重定向（覆盖） | 将命令的标准输出保存到指定文件，**会清空文件原有内容** | `ls -l > filelist.txt` |
| `>>`| 输出重定向（追加） | 将命令的标准输出**追加写入**到指定文件末尾，不破坏原数据 | `echo "New Log" >> app.log` |
| `<` | 输入重定向 | 让命令从指定文件中读取数据，替代键盘输入 | `wc -l < /etc/passwd` |
| `2>`| 错误重定向（覆盖） | 专门收集并重定向进程的报错信息（STDERR），隔离正常输出 | `cat /etc/shadow 2> error.log` |
| `2>&1`| 错误合流重定向 | 将标准错误（2）重定向合并到标准输出（1）中统一收集 | `cmd > all.log 2>&1` |

#### 2. 深入对比：长文本展示与分页查看工具 (`cat` vs `more` vs `less`)

当面对几十万行的大型日志或系统字典时，直接用 `cat` 会导致终端“刷屏卡顿”。Linux 提供了分页查看工具：

```text
┌──────────────┐     一次性全量输出（刷屏）
│     cat      ├─────────────────────────────────────────► 适合几行到几十行的小文件
└──────────────┘
┌──────────────┐     按屏向下翻阅（显示已读百分比，回退受限）
│     more     ├─────────────────────────────────────────► 传统基础分页器
└──────────────┘
┌──────────────┐     前后随意滚动、正则搜词、按需加载内存（极度推荐！）
│     less     ├─────────────────────────────────────────► 生产排查大日志首选
└──────────────┘
```

##### (1) `more`：基础分页器常用按键
- `Space`（空格键）：向下翻整屏
- `Enter`（回车键）：向下滚动单行
- `b`：向上翻一屏
- `q`：退出 `more`

##### (2) `less`：“Less is More”增强查看器常用按键（重点掌握）
`less` 不会在打开时全量读取整个大文件，加载极大文件也能秒开，是资深系统工程师的必备利器：
- `Space` / `PageDown`：向下翻一页；`PageUp`：向上翻一页
- `↓` / `↑` 方向键：向下 / 向上逐行平滑滚动
- `g`：瞬间跳转到文件**第一行（顶部）**
- `G`：瞬间跳转到文件**最后一行（末尾）**
- `/关键词`：向前搜索关键词（高亮显示），按 `n` 查看下一个匹配，按 `N` 查看上一个
- `?关键词`：向后搜索关键词
- `q`：安全退出 `less` 返回命令行

##### (3) 常用自由练习：
```bash
# 练习 1: 用 less 分页查看系统用户字典文件
less /etc/passwd
# 在里面输入 /bash 搜索关键字，按 n 查找下一个，按 q 退出

# 练习 2: 结合管道使用 less 缓冲长命令输出
ps aux | less
```

#### 3. 必须掌握的清单一：管道与常用文本清洗工具表

管道符 `|` 的核心作用是将**前一个命令的标准输出（STDOUT）**，无缝接入作为**后一个命令的标准输入（STDIN）**：

| 命令 | 常用核心选项 | 功能描述 | 演练示例 |
| :--- | :--- | :--- | :--- |
| `|` (管道) | 无 | 串联进程，前一个命令的输出作为后一个命令的输入 | `cat /etc/passwd \| wc -l` |
| `more` | `+<行号>` | 从指定行开始分页查看文件 | `more +10 /etc/passwd` |
| `less` | `-N` (显示行号) | 交互式高性能分页查看与检索 | `less -N /var/log/syslog` |
| `head` / `tail` | `-n <行数>`, `-f` (追踪) | 查看文本前 N 行或末尾 N 行 | `head -n 5 log.txt` |
| `wc` | `-l` (行), `-w` (词), `-c` (字节) | 统计文本行数、单词数或字节数 | `wc -l access.log` |
| `sort` | `-n` (按数值), `-r` (反向逆序), `-k <列>` | 对文本行按行或指定列排序 | `sort -nr -k 2 data.txt` |
| `uniq` | `-c` (统计重复频次), `-d` (仅显示重复) | 去除相邻重复行（**必须先配合 sort 排序**） | `sort ip.txt \| uniq -c` |
| `cut` | `-d '<分隔符>' -f <列号>` | 按指定分隔符提取文本中的特定列 | `cut -d ':' -f 1 /etc/passwd` |
| `tr` | `'[a-z]' '[A-Z]'`, `-d '<字符>'` | 字符转换或删除特定字符 | `echo "hello" \| tr 'a-z' 'A-Z'` |
| `tee` | `-a` (追加) | 双向重定向：既在屏幕打印，又写入文件 | `ls \| tee output.txt` |

#### 4. 必须掌握的清单二：文本三剑客（Grep / Sed / Awk）语法精讲

##### (1) Grep：文本内容检索行过滤器
- **语法**：`grep [选项] '匹配模式' 文件名`
- **核心选项速查**：
  - `-i`：忽略大小写（如匹配 `error` 和 `ERROR`）
  - `-n`：在每行输出前面附带行号
  - `-v`：**反向匹配**（反向排除，过滤掉包含该模式的行）
  - `-c`：统计匹配到的总行数
  - `-E`：开启扩展正则表达式（支持 `(a|b)`、`+` 等复杂模式）
- **高频演练**：
  ```bash
  # 查找包含 root 的行并显示行号
  grep -n "root" /etc/passwd

  # 排除所有以 '#' 开头的注释行以及空白行（查看配置文件有效干货）
  grep -v "^#" /etc/login.defs | grep -v "^$"
  ```

##### (2) Sed：非交互式流编辑器（行处理）
- **语法**：`sed [选项] '编辑指令' 文件名`
- **核心指令速查**：
  - `p`：打印匹配行（通常搭配 `-n` 静默参数使用）
  - `d`：删除匹配行
  - `s/old/new/g`：**最常用替换指令**，将匹配到的 `old` 替换为 `new`（`g` 代表全局替换）
- **高频演练**：
  ```bash
  # 打印第 2 到第 5 行
  sed -n '2,5p' /etc/passwd

  # 将输出流中所有的 127.0.0.1 替换为 0.0.0.0
  echo "listen 127.0.0.1:80" | sed 's/127.0.0.1/0.0.0.0/g'

  # 删除文本中所有包含 "debug" 的测试行
  sed '/debug/d' test.log
  ```

##### (3) Awk：按列切分与报表统计语言（列处理）
- **语法**：`awk -F '<分隔符>' '{动作}' 文件名`
- **核心内置变量速查**：
  - `$0`：代表整行完整文本
  - `$1`, `$2`, ... `$N`：代表按分隔符切片后的第 1 列、第 2 列...
  - `NF` (Number of Fields)：代表当前行的总列数（`$NF` 即最后一列）
  - `NR` (Number of Records)：代表当前处理的行号
- **高频演练**：
  ```bash
  # 以冒号 ':' 为分隔符，只提取 /etc/passwd 的用户名（第1列）与默认Shell（最后一列）
  awk -F ':' '{print "User: " $1 "  -> Shell: " $NF}' /etc/passwd

  # 筛选第 3 列 UID 大于等于 1000 的普通用户并输出
  awk -F ':' '$3 >= 1000 {print $1, $3}' /etc/passwd
  ```

#### 5. 黄金组合公式演练：Top N 频次统计流水线

在生产运维与安全分析中，**统计某项指标出现频次前 N 名**是工业级经典模板：
```bash
提取目标列 | 排序 | 频次统计去重 | 按数字逆序排序 | 截取前 N 项
  awk/cut   | sort |   uniq -c    |    sort -nr    |   head -n N
```
*例如：统计测试数据中登录失败次数最多的前 3 个 IP：*
```bash
# 模拟演示
cat << 'EOF' > ip_test.txt
192.168.1.10
10.0.0.1
192.168.1.10
172.16.0.5
192.168.1.10
10.0.0.1
EOF

cat ip_test.txt | sort | uniq -c | sort -nr | head -n 3
# 输出结果：
#   3 192.168.1.10
#   2 10.0.0.1
#   1 172.16.0.5
```

### Part B：任务挑战 —— Web 服务器恶意攻击与异常流量应急分析

#### 1. 业务场景
“阿波罗监控平台”发出紧急告警：生产环境的 Web 服务器在今日凌晨遭遇异常流量冲击，网站部分接口响应缓慢并频发 500 内部服务错误。

主管将当时的 Web 访问日志导出为 `/var/log/nginx/access.log`。你作为安全分析工程师，需要使用**分页工具、管道流与三剑客**对该日志进行深度切片分析，完成：
1. 使用 `less` 交互式排查大日志特征；
2. 定位针对接口的 SQL 注入攻击与未授权扫描；
3. 统计发起攻击最猛烈的高危 IP（Top 3）；
4. 统计全站 HTTP 响应状态码分布，评估故障范围；
5. 格式化生成安全排错审计报告 `~/traffic_audit.txt` 并签名交付。

---

#### 2. 操作步骤

##### 步骤一：模拟环境准备（构建生产环境访问日志）
在终端中执行以下命令，在 `/var/log/nginx/access.log` 中生成包含正常业务流量与恶意攻击流量的模拟日志：
```bash
sudo mkdir -p /var/log/nginx
cat << 'EOF' | sudo tee /var/log/nginx/access.log
192.168.1.105 - - [21/Sep/2026:02:10:01 +0800] "GET /index.html HTTP/1.1" 200 4521
10.0.2.15 - - [21/Sep/2026:02:10:05 +0800] "GET /api/user/profile HTTP/1.1" 200 1024
203.0.113.45 - - [21/Sep/2026:02:11:12 +0800] "GET /admin/login.php HTTP/1.1" 404 280
203.0.113.45 - - [21/Sep/2026:02:11:15 +0800] "GET /admin/db.sql HTTP/1.1" 404 280
198.51.100.88 - - [21/Sep/2026:02:12:00 +0800] "GET /api/goods?id=1' OR 1=1-- HTTP/1.1" 500 520
198.51.100.88 - - [21/Sep/2026:02:12:03 +0800] "GET /api/goods?id=2' UNION SELECT *-- HTTP/1.1" 500 520
198.51.100.88 - - [21/Sep/2026:02:12:08 +0800] "GET /api/goods?id=3' OR 'a'='a HTTP/1.1" 500 520

```
**如果不想打字，可以通过vi/vim复制进去，但请放过EOF这个标记。**

##### 步骤二：日志总体规模核查与交互式分页浏览 (`wc`, `head`, `tail`, `more`, `less`)
1. 使用 `wc -l` 统计日志文件的总请求数。
2. 使用 `head -n 2` 与 `tail -n 2` 分别查看该日志的最早记录与最新记录。
3. **分页交互实战**：使用 `less -N /var/log/nginx/access.log` 打开日志：
   - 按 `PageDown` / `PageUp` 体验翻页；
   - 键入 `/UNION` 并回车，体验交互式定位 SQL 注入位置；
   - 按 `q` 退出 `less`。

##### 步骤三：SQL 注入与恶意攻击请求检索 (`grep`)
1. 使用 `grep` 检索所有包含 SQL 注入特征关键字（如 `UNION` 或 `OR 1=1`）的恶意攻击日志，输出包含行号（`-n`）。
2. 检索所有响应状态码为 `404` 的目录扫描请求，并使用 `wc -l` 统计被扫描刺探的次数。

##### 步骤四：高危恶意 IP 排查 Top 3 (`awk`, `sort`, `uniq`, `head`)
1. 使用 `awk '{print $1}'` 提取出日志中所有的源 IP 地址。
2. 组合应用 `sort | uniq -c | sort -nr | head -n 3` 流水线，统计并输出请求频次排名前 3 的高危 IP 地址列表。

##### 步骤五：HTTP 响应状态码健康度分布统计 (`awk`, `sort`, `uniq`)
1. 观察日志格式，HTTP 状态码位于第 9 列（`$9`）。
2. 使用 `awk '{print $9}'` 提取状态码列，配合 `sort | uniq -c` 统计 200、304、404、500 各类状态码的发生次数。

##### 步骤六：敏感字段日志脱敏与摘要提取 (`sed`)
1. 在生产安全审计中，需将所有访问者 IP 的最后一位掩盖脱敏为 `*`（例如将 `198.51.100.88` 脱敏为 `198.51.100.*`）。
2. 运用 `sed 's/\.[0-9]\+ /.* /'` 或精准正则，生成一份脱敏后的攻击日志样本。

##### 步骤七：生成安全排错审计报告与成果签名交付 (`traffic_audit.txt`)
将上述各阶段分析结果规范写入报告文件 `~/traffic_audit.txt`：
```bash
# 1. 写入报告标题与日志总量
echo "==========================================" > ~/traffic_audit.txt
echo "    Apollo Web Traffic Security Report    " >> ~/traffic_audit.txt
echo "==========================================" >> ~/traffic_audit.txt
echo -n "Total Request Count: " >> ~/traffic_audit.txt
wc -l /var/log/nginx/access.log | awk '{print $1}' >> ~/traffic_audit.txt

# 2. 写入检测到的 SQL 注入攻击行
echo -e "\n[Detected SQL Injection Attacks]:" >> ~/traffic_audit.txt
grep -E "(OR 1=1|UNION SELECT)" /var/log/nginx/access.log >> ~/traffic_audit.txt

# 3. 写入请求频次 Top 3 高危 IP
echo -e "\n[Top 3 Most Active IP Addresses]:" >> ~/traffic_audit.txt
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -nr | head -n 3 >> ~/traffic_audit.txt

# 4. 写入 HTTP 状态码分布统计
echo -e "\n[HTTP Status Code Distribution]:" >> ~/traffic_audit.txt
awk '{print $9}' /var/log/nginx/access.log | sort | uniq -c | sort -nr >> ~/traffic_audit.txt

# 5. 写入脱敏后的日志前 5 行样例
echo -e "\n[Masked IP Sample (First 5 Lines)]:" >> ~/traffic_audit.txt
head -n 5 /var/log/nginx/access.log | sed -E 's/([0-9]+\.[0-9]+\.[0-9]+)\.[0-9]+/\1.*/' >> ~/traffic_audit.txt

# 6. 追加学生签名
echo -e "\n==========================================" >> ~/traffic_audit.txt
echo "Student_ID: 20260001" >> ~/traffic_audit.txt
echo "Student_Name: ZhangSan" >> ~/traffic_audit.txt
echo "Audit_Date: $(date +'%Y-%m-%d')" >> ~/traffic_audit.txt
echo "Audit_Verdict: THREAT_DETECTED_ACTION_REQUIRED" >> ~/traffic_audit.txt
```

1. **`cat`、`more` 与 `less` 的选型决策**：在生产环境中查看一个 5GB 的大型日志文件时，为什么严禁直接运行 `cat huge.log`？`more` 与 `less` 谁更胜任？为什么？（提示：内存读取机制与向前向后翻页支持度）。
2. **为什么必须先 `sort` 才能接 `uniq`？** 如果直接对未经排序的文本运行 `uniq -c`，会出现什么问题？（提示：`uniq` 的工作原理是比较相邻行）。
3. **重定向覆盖与追加的区别**：如果在构建报告时误将所有的 `>>` 全都写成了 `>`，最终报告文件里会剩下什么内容？在编写长篇自动化排错脚本时，有什么好习惯可以防止此误操作？
