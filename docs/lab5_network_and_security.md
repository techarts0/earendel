## 实验五：网络、安全及防火墙配置

- **适用课程**：Linux 操作系统
- **推荐学时**：3 学时 (讲授 1 学时，练习 2 学时)
- **实验平台**：Earendel Web OS [https://earendel.techarts.cn]

---

### 实验目标

1. **掌握网络状态探测与排障**：熟练使用 `ip`, `ping`, `curl` 等工具进行网络连通性测试与接口配置查看。
2. **精通端口与服务监控**：使用 `ss` 或 `netstat` 监控系统监听端口，找出占用特定端口的幕后进程。
3. **理解主机安全与防火墙机制**：掌握主机层面的防火墙策略配置（如 `ufw` 或 `iptables` 规则），实现端口的精准放行与封堵，防范恶意扫描。

### Part A：核心知识点解析与自由练习

---

#### 1. 理论精讲：网络配置与连通性测试

> [!NOTE]
> **预备理论**：网络是服务器的生命线。作为一个运维工程师，你必须能够快速回答三个问题：我的 IP 是多少？我能连到外网吗？指定的网络服务通不通？

##### (1) 查看网络接口与 IP 地址 (`ip addr`)
- 过去常用的 `ifconfig` 现已逐渐被 `ip` 命令家族替代。
- `ip addr` (或简写为 `ip a`)：查看本机所有网卡的 IP 地址及 MAC 地址。
  - `lo` (Loopback)：本地回环接口，IP 永远是 `127.0.0.1`，用于本机内部服务通信。
  - `eth0` / `ens33` 等：物理或虚拟网卡，通常配置了对外的局域网或公网 IP。

##### (2) 连通性与路由测试 (`ping` 与 `traceroute`)
- `ping <目标IP或域名>`：发送 ICMP 回显请求，测试是否能与目标主机通信，以及网络延迟情况。
  - *注意：在 Linux 下，`ping` 默认会无限发送，必须按 `Ctrl + C` 停止，或使用 `ping -c 4 baidu.com` 指定发送次数。*
- `traceroute <目标>`：追踪数据包到达目标主机所经过的路由节点。

##### (3) HTTP 服务探测 (`curl`)
- `curl http://localhost:9090`：在终端直接发起 HTTP 请求，抓取网页代码，常用于测试 Web 服务是否正常响应。

---

#### 2. 服务端口与连接状态监控 (`ss` / `netstat`)

当一个服务（如 Nginx、数据库）启动时，它会在系统上监听一个特定的网络端口（Port，范围 1~65535）。
- `ss -tuln`：现代 Linux 推荐的网络连接查看工具（比 `netstat` 更快）。
  - `-t`：显示 TCP 端口。
  - `-u`：显示 UDP 端口。
  - `-l`：仅显示正在监听 (LISTEN) 的端口。
  - `-n`：以数字形式显示 IP 和端口号，不解析域名，速度更快。
- `ss -tulnp | grep 9090`：加上 `-p` 选项可以显示是哪个进程（PID）在占用该端口（需要 root 权限）。

---

#### 3. Linux 主机防火墙初步

为了抵御攻击，服务器必须开启防火墙，遵循“默认拒绝，按需放行”的安全基线。
Ubuntu/Debian 系列常使用 `ufw` (Uncomplicated Firewall) 来简化配置。
- `sudo ufw status`：查看防火墙状态及当前规则。
- `sudo ufw enable`：开启防火墙（**警告**：如果你在使用 SSH 远程连接，开启前务必先放行 22 端口，否则会把你自己踢下线！）。
- `sudo ufw allow 22/tcp`：放行 SSH 端口。
- `sudo ufw allow 9090/tcp`：放行指定的业务端口。
- `sudo ufw deny from 192.168.1.100`：封锁来自特定恶意 IP 的所有请求。

### Part B：任务挑战 —— 业务端口审计与恶意流量封堵

#### 1. 业务背景
“阿波罗研发中心”的微服务节点近期频繁遭到来源不明的恶意端口扫描。安全部门要求你：
1. 探明当前系统到底有哪些端口暴露在外。
2. 启动系统防火墙，仅放行 SSH (22) 和核心业务端口 (9090)。
3. 发现并封堵一个已被确认为黑客肉鸡的恶意 IP 地址。

---

#### 2. 挑战操作步骤

##### 步骤一：模拟启动 Apollo 业务监听
为了模拟真实场景，我们使用 `nc` (Netcat) 工具在后台伪造一个运行在 9090 端口的微服务进程。
```bash
# 启动一个简易的监听进程
nohup nc -l -p 9090 >/dev/null 2>&1 &
```

##### 步骤二：端口状态审计与服务探测
1. 使用 `ss` 命令检查本地是否真的有服务在监听 9090 端口：
   ```bash
   ss -tulnp | grep 9090
   ```
   *记下输出结果，稍后写入审计报告。*
2. 使用 `curl` 探测本机的服务（即便它是伪造的，也会建立连接并挂起，按 `Ctrl+C` 中止即可）：
   ```bash
   curl -v http://127.0.0.1:9090
   ```

##### 步骤三：启用并配置 UFW 防火墙策略
*(注：Earendel 平台底层可能限制了部分真实内核防火墙能力，但我们在此演练策略配置流程)*
1. **非常重要**：在启用防火墙前，**必须先放行 22 端口**（SSH），这是运维的生命线！
   ```bash
   sudo ufw allow 22/tcp
   ```
2. 放行我们的核心业务端口 `9090`：
   ```bash
   sudo ufw allow 9090/tcp
   ```
3. 启用防火墙系统：
   ```bash
   sudo ufw enable
   ```
   *（如果提示是否继续，输入 `y` 确认）*
4. 检查防火墙状态，确认规则已生效：
   ```bash
   sudo ufw status numbered
   ```

##### 步骤四：精准封杀恶意 IP
安全监控报警，IP `203.0.113.55` 正在对我们的服务器发起密码爆破。你需要立即在网络层阻断它的所有连接。
1. 添加拦截规则：
   ```bash
   sudo ufw insert 1 deny from 203.0.113.55
   ```
   *(注：`insert 1` 表示将该拦截规则插入到第 1 条，优先级最高。防火墙规则是从上往下匹配的。)*
2. 再次查看防火墙状态，确认封堵规则位于最顶部：
   ```bash
   sudo ufw status numbered
   ```

##### 步骤五：生成网络安全审计报告 (`net_audit.txt`)
将今天的安全加固成果汇报给安全部门。
```bash
# 1. 导出网卡及 IP 信息
echo "--- Network Interfaces ---" > ~/net_audit.txt
ip addr >> ~/net_audit.txt

# 2. 导出端口监听状态
echo -e "\n--- Listening Ports ---" >> ~/net_audit.txt
ss -tuln >> ~/net_audit.txt

# 3. 导出防火墙安全策略
echo -e "\n--- Firewall Security Policies ---" >> ~/net_audit.txt
sudo ufw status numbered >> ~/net_audit.txt

# 4. 追加签名
echo -e "\n--- Student Signature ---" >> ~/net_audit.txt
echo "Student_ID: 20260001" >> ~/net_audit.txt
echo "Student_Name: ZhangSan" >> ~/net_audit.txt
```

### 思考与进阶拓展
1. **规则优先级陷阱**：如果你先配置了 `allow from any to any port 9090`，然后再配置 `deny from 203.0.113.55`，那个恶意 IP 还能访问 9090 端口吗？为什么防火墙规则的顺序极其重要？
2. **Ping 与 ICMP**：很多大型企业的服务器（比如 github.com）是可以正常访问网页的，但是你 `ping` 它却没有反应（Request timeout）。结合本课知识，思考他们是如何通过防火墙实现这一点的？这样做有什么好处？
